# ADR-004：工具权限分级设计

> **状态**：已采纳
> **日期**：2026-06-12
> **决策者**：宇诚
> **影响范围**：AgentForge 工具系统

---

## 背景

Agent 需要调用各种工具完成任务，但不同角色的 Agent 应该有不同的工具权限：
- Reviewer 只需要读代码，不应该能修改或执行
- Coder 需要读写文件，但不一定需要执行 Shell
- 全权限 Agent 才能执行 Shell 命令

需要一种机制来限制 Agent 的工具权限，防止越权操作。

---

## 备选方案

### 方案 A：三级权限模型（我们的选择）

READ / WRITE / EXECUTE 三个级别，递增包含：
- READ：只读操作
- WRITE：只读 + 写入
- EXECUTE：只读 + 写入 + 执行

### 方案 B：RBAC（基于角色的访问控制）

定义角色（如 "reader"、"developer"、"admin"），每个角色关联一组工具权限。

❌ 不选。角色定义增加了配置复杂度，对于 Agent 数量有限的场景过于重量。三级权限已足够覆盖当前需求。

### 方案 C：工具级黑白名单

每个 Agent 直接指定允许/禁止的工具列表，没有分级概念。

❌ 不选。每个 Agent 手动维护工具列表，新增工具时要逐个更新，维护成本高。三级权限的递增包含设计更简洁。

---

## 决定

选择方案 A（三级权限）。理由：

1. **简单直观**：三个级别覆盖了大多数场景，不需要复杂的角色定义
2. **递增包含**：`get_tools(WRITE)` 自动包含 READ 工具，符合直觉
3. **易于扩展**：未来可以加 ADMIN 级别（如删除文件、网络请求）
4. **与最小权限原则一致**：每个 Agent 只拥有完成任务所需的最小工具集

### 风险

- 三级可能不够细粒度（如区分"写文件"和"创建文件"）
- 但对于当前阶段足够，后续可以细化

## 执行层边界：沙箱与黑名单（2026-09-12 增补）

权限模型解决的是"Agent 能看到哪些工具"，执行层还需要回答
"工具能触碰哪些路径/命令"：

### 文件沙箱（tools/sandbox.py）

- 相对路径锚定沙箱根（默认进程 cwd，`set_sandbox_root` 可切换）
- `resolve()` 后越出沙箱根的绝对路径与 `..` 逃逸一律拒绝
- `.env*` 敏感文件无论位置一律拒绝读写——API Key 不应进入 LLM 上下文

### Shell 黑名单（tools/shell_tools.py）

- 子串名单 + 正则名单双层：覆盖 `rm` 递归变体、`rmdir /s`、
  `chmod -R 777`、块设备写入等参数变形
- `format` 采用锚定匹配，避免误伤 `clang-format`

### 残余风险（如实声明）

黑名单无法防御所有变体（如 `python -c "import shutil; ..."`），
文件沙箱不限制沙箱根内的破坏性写入。当前防线顺序：
权限过滤（构建时）→ 沙箱/黑名单（执行时）→ 超时/截断（兜底）。
**生产环境必须配合容器级隔离（Docker namespace / 无网络沙箱）。**
